# Kubeon — notes for Claude

Native Kubernetes IDE (Lens-like) in Go: Gio UI + vendored k9s engine.

## Hard rules
- **Never use the kube contexts configured on this machine** (`~/.kube/config`, `$KUBECONFIG`).
  Only the disposable kind cluster: `make dev-up` → `.dev/kubeconfig` (context `kind-kubeon-dev`).
  Always build/run/test with the `dev` tag (it refuses any other kubeconfig/context) and
  `env -u KUBECONFIG`; every kubectl goes through `./scripts/dev-cluster.sh kubectl …`.
- No paid LLM calls without asking: AI tests use mock servers or local Ollama
  (`KUBEON_TEST_OLLAMA_MODEL=llama3.1:8b`).

## Build / test
- Gio tags: `nox11,novulkan` (X11/Vulkan headers not installed; Wayland only).
- `make test` (unit), `make test-int` (integration + headless UI screenshots in `.dev/shots/`, packages
  run serially since they mutate the shared cluster), `make run`. `-race` on test-int must report 0 races.
- `third_party/k9s` is generated by `scripts/vendor-k9s.sh` (overlays in `third_party/_k9s-overlay`,
  fixes in `third_party/_k9s-patches`: private DAO/renderer per table, sequential xray, default log container);
  `third_party/gio` by `scripts/vendor-gio.sh` (patches in `third_party/_gio-patches`). Don't hand-edit;
  to change Gio, edit the vendored file and regenerate the matching patch (verify it reapplies cleanly).

## Packaging
- Self-update (`internal/update`) installs only releases whose SHA256SUMS.txt verifies with the built-in
  ed25519 public key; the private key is `.dev/update-signing.key` locally and the `UPDATE_SIGNING_KEY`
  repo secret in CI. Never print, commit or regenerate it. Dev builds never update.
- Packages are published to the public repo `twoojoo/kubeon-releases` (source repo is private); the
  updater reads its latest release. Creating public repos/surfaces is the user's call.
- `scripts/notices.sh` builds THIRD_PARTY_NOTICES.txt (k9s is inside our module: added by hand).
- `make package-linux` (Docker), `make package-windows` (cross, pure Go), `make package-macos` (Mac only;
  never verified locally — CI `macos-14` job is the only check). Output in `dist/`.
- Smoke-testing a release binary locally: always `env -u KUBECONFIG`, explicit
  `--kubeconfig .dev/kubeconfig --context kind-kubeon-dev`, `KUBEON_CONFIG_DIR`/`KUBECACHEDIR` under `.dev/`.
- Windows: unit/headless tests run under wine (`GOOS=windows go test -c`, `WINEPREFIX=.dev/wine`); real
  windows don't open in wine (no `EnableMouseInPointer`), that's expected.

## Layout
- `internal/backend` facade over k9s (watches, actions, logs, exec, port-forward, helm, xray, health).
- `internal/ui` Gio app; `internal/ai` assistant (Anthropic SDK + OpenAI-compatible providers, read-only tools, redaction).
- `internal/safety` dev-build kubeconfig/context guard; `internal/notify` notifications per OS
  (`notify_dbus.go` / `_darwin` / `_windows`); `internal/desktop` per-OS integration.
- `internal/prefs` user preferences (`~/.config/kubeon/settings.json`): theme, per-context policies
  (protected/read-only), pinned port-forwards, bookmarks. UI mutations must go through
  `allowMutation` / `guard` / `confirmMutation` (internal/ui/policy.go).
- Tests that touch preferences set `KUBEON_CONFIG_DIR` to a dir under `.dev/`.
