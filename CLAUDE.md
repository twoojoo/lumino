# Lumino — notes for Claude

Native database IDE (DBeaver/Beekeeper alternative) in Go: Gio UI (forked from Kubeon) on top of a
driver-neutral database API with one adapter per database.

## Hard rules
- **Never connect to databases configured on this machine** (other projects run Postgres on 5432/5433).
  Only the disposable ones of `scripts/dbs/compose.yml` (`make db-up`, 127.0.0.1:55xxx) and SQLite files
  under `.dev/`. Build/run/test with the `dev` tag: `internal/safety` refuses anything else, keeps
  settings in `.dev/config` and uses an in-memory keyring.
- No paid LLM calls without asking: AI tests use mock servers (`internal/ai/*_test.go`) or local Ollama.

## Build / test
- Gio tags: `nox11,novulkan` (X11/Vulkan headers not installed; Wayland only).
- `make test` (unit), `make db-up` then `make test-int` (conformance suite of every adapter in
  `internal/db/conformance` + headless UI tests with screenshots in `.dev/shots/`), `make run`.
- Conformance: `internal/db/dbtest` runs the same checks on every database (metadata, DDL round trip,
  streaming, cancel, transactions, read-only sessions, row editing, type round trips). Fixtures per
  dialect in `internal/db/dbtest/fixtures/*.sql`. A new adapter must pass it. Document databases run
  `dbtest.RunDocuments` instead (fixture `fixtures/mongo.js`, targets mongo 55017 replica set, mongo-secure 55019
  keyFile replica set with TLS required + SCRAM/X.509 users, ferretdb 55018; sharded cluster shard-cfg/shard-a/shard-b
  behind mongos 55020, set up by `scripts/dbs/mongos-init.js`, used by `conformance/mongo_cluster_test.go`). `make test-int` writes the output of
  failed tests to `.dev/test-int-failures.txt` (`scripts/testreport`).
- `third_party/gio` is generated by `scripts/vendor-gio.sh` (patches in `third_party/_gio-patches`).

## Layout
- `internal/db`: API (`Driver`, `Conn`, `Session`, `Result`, `Catalog`, `Language`, `Dialect`), values, edits
  (`Apply`: native `ChangeApplier` sessions or SQL `ApplyChanges`), DDL helpers, statement classification,
  SSH tunnels, TLS. `Conn.Language()` is the only query-language entry point of UI and AI (lexing, split,
  classify for policies, completion context, browse/count/filter, drop/templates, edit preview, insert export,
  explain); SQL adapters get `SQLLanguage` over their `Dialect` (`db.DialectOf(conn)` for SQL-only code).
  `internal/db/sqlx`: line-based lexer + script splitter (dollar quotes, DELIMITER, GO, `/`, SET TERM).
  `internal/db/sqlbase`: database/sql implementation shared by adapters (hooks for cancel, kinds…).
  `internal/db/adapters/*`: postgres, cockroach, mysql (mysql/mariadb/tidb), sqlite (modernc), mssql,
  oracle (go-ora), clickhouse, firebird, cassandra (gocql, native session), trino, mongo (mongo-go-driver v2,
  MongoDB 5.0+ and FerretDB: databases = schemas, collections/views, fields inferred by sampling; console language =
  mongosh statements parsed in `shell.go` and run as server commands, anything else (variables, loops) runs in a
  per-session goja runtime (`js.go`) whose operations are classified with their actual arguments and checked at run
  time: read-only sessions refuse writes, `db.Guard` (console: confirmation on protected connections; AI: refusal)
  decides the others; `ChangeApplier` edits keep BSON types; script documents are `docDyn` proxies converted field by
  field). Results hand out `db.Document`s converted to `DocNode` on first `Node()` (tree/JSON views, edits, exports);
  `Completion` lists collections only, fields come per collection from `db.FieldCompleter`; the `readPreference`
  parameter (a `db.Info.Choices` entry of the form) applies to reading statements and the navigator, transactions
  and edits use the primary. Field paths (`db.JoinFieldPath`/`SplitFieldPath`)
  quote names with dots or a leading `$` (`a."b.c"`): such paths are updated by `$setField` pipelines; nested
  documents are ordered Extended JSON text cells; result columns grow when later documents bring new fields.
  All pure Go.
- `internal/ui`: Gio app. `editor.go`/`editbuf.go`/`completion.go`/`findbar.go` (SQL editor),
  `grid.go` (data grid), `console.go`, `tableview.go`, `sidebar.go`, `connform.go`, `conns.go`
  (connection state + metadata cache), `aipanel.go`. Document databases (`db.DocumentLanguage`, results with
  `db.DocumentResult`): query bar with projection/sort/limit (`tableview.go`, single-line `CodeEditor`s),
  tree/JSON views (`docview.go`), document editing by path (`tabledocs.go`, `doceditor.go`). Management features
  through `db.DocumentTools` (adapter `tools.go`) and `DocumentLanguage.AdminStatement` (`admin.go`, reviewed and run
  under the policies by `reviewRun`, `docadmin.go`): schema view, indexes, validation, explain (`doctable.go`), pipeline
  builder (`pipeline.go`), collection stats + index advisor + profiler slow queries (`advisor.go`, adapter
  `advisor.go`), change streams and server activity (`livetabs.go`), users, import, SQL translation
  (`docdialogs.go`, adapter `sqltranslate.go`), document exports (`export.go` docs-* formats), replica set / sharding
  status (`cluster.go`, adapter `cluster.go`, `DocumentTools.Topology`) and export of statements to Go/Python/Node/
  Java/C# driver code (`CodeDialog` in `cluster.go`, adapter `codegen.go`; generated Go programs are built and run by
  `conformance/mongo_cluster_test.go`).
- `internal/prefs` (settings, no secrets), `internal/secrets` (OS keyring), `internal/history`,
  `internal/knownhosts` (SSH TOFU), `internal/ai` (assistant: providers, read-only DB tools, proposals).
- `internal/site`: website (GitHub Pages, `.github/workflows/pages.yml`) generated by `make site`; one page
  per database in `databases.go` (ports/caps read from the adapters, the test fails if a driver has no page),
  screenshots from `make site-shots` (headless SQLite UI test). Keep claims verifiable in the code.
- Mutations go through policies: read-only connections block writes, protected (production) ones
  confirm (typed for destructive statements) and start consoles in manual transaction mode.

## Packaging
- Self-update (`internal/update`) installs only releases whose SHA256SUMS.txt verifies with the built-in
  ed25519 public key; the private key is `.dev/update-signing.key` locally and the `UPDATE_SIGNING_KEY`
  repo secret in CI. Never print, commit or regenerate it. Dev builds never update.
- Packages are published as GitHub releases of this repo (`twoojoo/lumino`, tag `v*` → CI job `release`).
- `make package-linux|windows|macos`, icons from `packaging/logo-source.png` (imported from an artwork
  with `go run ./scripts/logogen -src art.png`, then `make icons`: package icons, UI logo, website logo/favicon).
