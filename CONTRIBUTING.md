# Contributing to Lumino

Bug reports, ideas and pull requests are welcome. For larger changes (a new adapter, a new panel)
open an issue first so we can agree on the approach.

## Setup

You need Go (version in `go.mod`), Docker (for the test databases) and, on Linux, the Gio
development headers listed in `.github/workflows/ci.yml` (`GIO_LINUX_DEPS`).

```sh
make db-up      # disposable databases (docker compose, 127.0.0.1:55xxx); DBS="postgres mysql" for a subset
make run        # dev build: development databases only, settings in .dev/config
make test       # unit tests
make test-int   # conformance suite of every adapter + headless UI tests (screenshots in .dev/shots)
```

Dev builds (`dev` tag) refuse to connect to anything but the disposable databases and SQLite files
under `.dev/`, keep settings in `.dev/config` and use an in-memory keyring: your real connections and
passwords are never touched.

## Guidelines

- Run `make test` before sending a pull request, and `make test-int` when you touch the database
  layer or the UI (look at the screenshots in `.dev/shots/` after UI changes).
- A new or changed adapter must pass the conformance suite (`internal/db/dbtest`), with fixtures in
  `internal/db/dbtest/fixtures/<dialect>.sql`.
- Tests must not call paid LLM APIs: use the mock servers in `internal/ai/*_test.go`.
- `third_party/gio` is generated by `scripts/vendor-gio.sh`: change it through a patch in
  `third_party/_gio-patches`, not by editing the vendored files.
- Keep pull requests focused, with tests for the behaviour they change.

## Developer Certificate of Origin

Lumino is licensed under the GPL-3.0-or-later and contributions are accepted under the same license.
Every commit must be signed off, certifying the [Developer Certificate of Origin](https://developercertificate.org/):

```sh
git commit -s -m "Fix completion after schema-qualified names"
```

which adds a `Signed-off-by: Your Name <you@example.com>` line with your real name.
